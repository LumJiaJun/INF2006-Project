# Data Dictionary — StaySphere

## Status

The real Kaggle dataset ("Airbnb Listings and Reviews",
https://www.kaggle.com/datasets/toufikbhm/airbnb-listings-and-reviews)
has **not been downloaded or inspected yet**. This project currently
ships `data/sample/dummy_listings.csv` and `data/sample/dummy_reviews.csv`,
synthetic data generated by `data/generate_dummy_data.py` that follows
the publicly documented column names and types for that dataset.

**When the real dataset is downloaded**, run `python3 data/inspect_dataset.py <file>.csv`
(already written — see `data/README.md`) and update this document with
the actual schema, row/column counts, missing-value percentages and any
differences from what's listed below.
Do not assume the real file matches this schema exactly.

## listings (`data/sample/dummy_listings.csv`)

600 synthetic rows.

| Column | Type | Description | Used by |
|---|---|---|---|
| listing_id | int | Primary key | DB, app |
| name | string | Listing title | UI |
| host_id | int | Host identifier | DB relationship |
| host_since | date | Host join date | analytics |
| host_location | string | Host's stated location | analytics |
| host_response_time | categorical | Response speed bucket | ML feature, UI |
| host_response_rate | int (0-100) | % of messages responded to | ML feature |
| host_acceptance_rate | int (0-100) | % of requests accepted | ML feature |
| host_is_superhost | bool | Superhost badge | ML feature, UI |
| host_total_listings_count | int | Listings owned by host | ML feature |
| host_has_profile_pic | bool | Profile picture present | UI |
| host_identity_verified | bool | ID verification status | ML feature, UI |
| neighbourhood | string | Neighbourhood name | search filter, ML feature |
| district | string | District name | search filter |
| city | string | City | search filter, ML feature |
| latitude | float | Latitude (synthetic data: jittered around each city's real centre) | map view, admin heatmap |
| longitude | float | Longitude (synthetic data: jittered around each city's real centre) | map view, admin heatmap |
| property_type | categorical | e.g. Apartment, House | search filter, ML feature |
| room_type | categorical | Entire home/apt, Private room, Shared room | search filter, ML feature |
| accommodates | int | Guest capacity | search filter, ML feature |
| bedrooms | int | Bedroom count | search filter, ML feature |
| amenities | string | `\|`-delimited amenity list | UI, derived feature (amenity count) |
| price | float | Nightly price (SGD-equivalent) | booking, **ML target** |
| minimum_nights | int | Minimum stay | booking validation |
| maximum_nights | int | Maximum stay | booking validation |
| review_scores_rating | float (0-5) | Overall rating | UI, ML feature |
| review_scores_accuracy | float (0-5) | Sub-score | UI |
| review_scores_cleanliness | float (0-5) | Sub-score | UI |
| review_scores_checkin | float (0-5) | Sub-score | UI |
| review_scores_communication | float (0-5) | Sub-score | UI |
| review_scores_location | float (0-5) | Sub-score | UI |
| review_scores_value | float (0-5) | Sub-score | UI |
| instant_bookable | bool | Instant booking available | search filter |

Missing values: none (synthetic data has no nulls by construction).
The real dataset will very likely have missing values in
`host_response_rate`, `review_scores_*` and similar fields — this must
be re-documented once the real file is inspected.

## reviews (`data/sample/dummy_reviews.csv`)

3500 synthetic rows.

| Column | Type | Description |
|---|---|---|
| listing_id | int | Foreign key to listings |
| review_id | int | Primary key |
| date | date | Review date |
| reviewer_id | int | Reviewer identifier |

No review text/comment field exists in the documented schema for this
dataset, so no sentiment analysis is attempted anywhere in this
project. If the real dataset turns out to contain a comment field,
that would need to be added here explicitly before any text-based
feature is built.

## Application-only tables (not from the dataset)

Created by the backend, not seeded from CSV:

- `users` — registered accounts (id, name, email, password_hash, role, created_at)
- `bookings` — simulated bookings (id, listing_id, guest_id, check_in, check_out, guests, nights, nightly_price, total_amount, status, created_at)

See `docs/DATABASE_SCHEMA.md` for full schema and indexes.
