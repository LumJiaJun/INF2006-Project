# Application Teardown and FinOps State - 2026-10-02

## Scope

The Terraform-managed development application stack in `ap-southeast-1` was
destroyed after evidence collection to stop overnight application costs. The
separate encrypted S3 and KMS Terraform state bootstrap was intentionally
retained so the team can deploy the same configuration again.

## Reviewed plan

The saved application destroy plan was reviewed before approval:

```text
Plan: 0 to add, 0 to change, 125 to destroy.
```

The plan covered the application infrastructure only. It did not include the
separately managed Terraform backend.

## Recovery and completion

The first apply removed most resources but could not immediately delete Lambda
network interfaces or the versioned CloudTrail bucket. A transient DNS failure
also prevented Terraform from uploading its updated state. Terraform preserved
the exact recovery state locally instead of discarding it.

Before continuing, the remote backend was verified, the stale lock belonging to
the terminated local operation was removed, and the exact recovery state was
pushed to the backend. All versions and delete markers were then removed from
the CloudTrail bucket, and the former Lambda network interfaces were confirmed
available. A new saved destroy plan was reviewed and applied:

```text
Plan: 0 to add, 0 to change, 6 to destroy.
Apply complete! Resources: 0 added, 0 changed, 6 destroyed.
```

## Verification

- The application Terraform state contains zero managed resources.
- No project Lambda functions, application S3 buckets, ECR repository,
  CloudFront distribution, API Gateway API, VPC, WAF, or Cognito user pool
  remained in direct service listings after teardown.
- The two former operational-alert KMS keys are pending deletion under their
  configured safety windows.
- The encrypted Terraform state bucket and its bootstrap KMS key remain
  available and are not part of the application state.

## Remaining FinOps baseline

The recurring application resources with the most relevant idle cost, including
WAF and VPC interface endpoints, have been removed. The retained customer-managed
bootstrap KMS key still has a recurring key charge, and the small Terraform state
objects incur negligible S3 storage charges. Destroying the bootstrap requires a
separate deliberate process because it removes the shared deployment state and
is protected against accidental deletion.
